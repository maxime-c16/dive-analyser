# Account administration: three PRs, highest gain first

Three stacked PRs. Merge order is 1 → 2 → 3. Access studio is the selected UI direction, with consistent inline Identity, Security, Audit trail and Lifecycle tab pages and purpose-built mobile cards. The approved V3 Studio is integrated into the production account route in layer 3, with real ownership graphs, count-based change previews and inline tabs. All layouts use the same components and workflows; review fixtures use synthetic data and never enter the production router.

1. **Account workspace and binding QOL.** Dedicated administrator route; account header; profile editing with Save/Discard and navigation protection; searchable, linked-first bindings with explicit ownership consequences; paginated directory and preserved URL filters. Highest gain: faster, safer daily account editing.
2. **Security and accountability.** Paginated, account-scoped audit history and individual live session revocation; existing password reset and sign-out-all actions with explicit impact confirmation. Highest gain: explain changes and resolve account-security incidents using existing tables.
3. **Studio and access troubleshooting.** Approved V3 ownership graph and effective capability cards; real view/manage dive counts; read-only diagnostics using the production policy; resolver grants and removals with refreshed before/after previews and explicit confirmation; inline Identity, Security, Audit trail and Lifecycle tabs; mobile layouts and LAN review of the actual production components. Highest gain: explain access without impersonation or changing permissions.

Layouts: 01 — Command center with account health, an action queue and access context; 02 — Support desk with a guided case investigation and handoff; 03 — Access studio with an ownership graph, effective permission matrix and staged changes. Compare profile save/error recovery, ownership change staging, session revoke, history, access checks, case notes and proposed suspension/recovery flows in every layout. Validate desktop and narrow mobile widths, keyboard focus, error recovery and no page errors. No video recordings are produced; review uses the LAN URL.

Follow-ups, deliberately outside these three initial PRs: email delivery and recovery links, MFA, delegated administrator roles, temporary grants, timed suspension, account merging, stored support notes, and impersonation. These need distinct lifecycle/security decisions; no nonfunctional controls are exposed for them.
