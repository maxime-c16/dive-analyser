## HDR follow-up verification

The two previously reported browser-upload HDR regression failures reproduce
on the development laptop because its Homebrew ffmpeg lacks `zscale`.
Running the existing test function against the deployed backend's ffmpeg in a
separate Python process, with generated media in temporary storage, passes all
three cases: untagged 10-bit, PQ and HLG. No database, private media or live
application configuration was modified by this probe. This does not establish
visual correctness on every real camera clip.

The Mac ffmpeg supports `zscale`, but the old worker proxy command only scales
the 10-bit source and labels it BT.709. The follow-up worker change detects the
first video stream's transfer, tone maps PQ/HLG, sets frame and encoder SDR
metadata, and keeps H.264 8-bit plus fast-start. Generated-media tests on the Mac
cover 360p and 720p for SDR/PQ/HLG, verify actual decoded pixel differences from
simple relabeling, decode compatibility, color tags, fast-start order, and source
checksum preservation. Existing cached proxies are not regenerated by this fix.
Posters, durable ingestion packaging, backfill and a measured two-slot canary
remain separate stages.
